Technical Details

What the Parameters Mean

{% if sim_params and sim_params.algo_param_config %} {% if 'EpsTS' in sim_params.algo_param_config %}
EpsTS (Epsilon-Thompson Sampling)
Parameter ε controls exploration probability. With probability ε, a random arm is selected uniformly; otherwise, Thompson Sampling picks the best estimated arm. ε=0 is pure TS (exploit), ε=1 is pure random exploration.
{% endif %} {% if 'TSProbClip' in sim_params.algo_param_config %}
TSProbClip (TS with Probability Clipping)
Parameter p_clip caps the selection probability so each arm gets at least p_clip/K chance of being selected (K = number of arms). This prevents any arm from being completely ignored. p_clip=0 is pure TS, p_clip=1 guarantees at least 1/K probability per arm.
{% endif %} {% if 'TSTopUR' in sim_params.algo_param_config %}
TSTopUR (TS Top Uniform Random)
Parameter δ defines the "top" threshold. Instead of always picking the single best arm, considers all arms whose estimated reward is within δ of the best, then selects uniformly among them. δ=0 exploits the best only; larger δ explores more near-best arms.
{% endif %} {% else %}
EpsTS (Epsilon-Thompson Sampling)
Parameter ε controls exploration. ε=0 means pure Thompson Sampling (exploit), ε=1 means uniform random exploration.
{% endif %}

What is w?

The Step-to-Reward Conversion Rate w controls how much you value cumulative reward during the experiment versus reaching your desired statistical power quickly. At high w, the objective focuses on minimising the number of steps. At low w, maximising reward matters more. There is no single "correct" w — it depends on your experimental priorities.

As a rule of thumb: if your max achievable reward is R, then setting w between 0.05R and 0.1R provides a meaningful tradeoff. Setting w > R means you're purely minimizing experiment length with no regard for reward.

What is ECP-Reward?

ECP-reward measures how good an experiment is by balancing two things: how much reward it earns and how long the experiment runs. Running an experiment longer has a cost, and the parameter w controls how expensive that cost is. A larger w means that shorter experiments are preferred.

When you choose a value of w, we first find the algorithm that performs best at that value. That algorithm is treated as the optimal choice for your selected w.

The curve then shows how that same algorithm performs across all values of w. The y-axis shows relative ECP-reward, where 0 means the algorithm is optimal at that w, and higher values mean it performs worse than the best possible choice at that w.

This plot helps you understand how sensitive your algorithm choice is to the value of w, and how much performance you might lose if w is different from what you expected.

In addition to the selected algorithm, we also plot Thompson Sampling (TS) and Uniform Randomization (UR) as reference strategies.

These reference curves are shown for comparison. They help illustrate how the selected algorithm performs relative to two commonly used baselines: one that prioritize for reward (TS), and one that assigns actions uniformly at random for balanced exploration (UR).

Interpreting Results

The recommended parameter balances the exploration-exploitation tradeoff for your specific setting. Lower parameters generally favour exploitation (using what we know), while higher parameters favour exploration (gathering more information).

Error Decomposition

The results tables include three error metrics, all expressed as steps:

H1 Var (steps)
Standard error from finite H1 simulation repetitions. Power is a sample mean of binary outcomes; this column shows how much the "steps to reach power" estimate shifts by one SE. Reduce by increasing H1 reps.
H0 Var (steps)
Standard error from finite H0 reps at each grid point. The critical boundary is a quantile estimate with inherent variance. This column shows how perturbing the boundary by ±1 SE changes the steps estimate. Reduce by increasing H0 reps per location.
WC Bias (steps)
Worst-case interpolation bias from using a finite number of H0 grid points. The critical boundary is interpolated between grid points; this column bounds how much error that interpolation could introduce. Reduce by increasing H0 grid points.

Caveats:

  1. H0 variance introduces bias, not just variance. When the critical boundary is estimated with variance, power is biased toward 0.5 (Jensen's inequality). The H0 Var column captures the variance effect but not this additional bias. For reliable results, ensure H0 Var is small.
  2. WC Bias assumes within-bin monotonicity. The interpolation bias bound assumes the true critical boundary varies smoothly between grid points. In pathological cases (discontinuous algorithm behavior), actual bias could exceed this bound. Treat it as an indicator, not a guarantee.
